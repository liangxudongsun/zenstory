# 移除 LlamaIndex / Chroma，保留数据库文件检索

## Problem

本轮用户明确要求彻底移除没有投入使用的 LlamaIndex。托管环境已关闭 embedding 与异步索引，但 Agent 上下文和外部 Agent API 仍通过 LlamaIndex 服务取得数据库关键词结果；实例化该服务仍会打开 Chroma。本次删除不能让已有关键词检索失效，也不能删除卷上的素材原文件和反馈截图。

## Decision

清理边界（在代码改动前确定）：
- 从原服务提取已经在使用的数据库关键词匹配、排序、片段及项目/删除过滤；上下文和现有 `/agent/projects/{id}/search` 改用该服务，保持鉴权、限流与响应字段。
- 删除 LlamaIndex / Chroma 服务、后台索引线程及所有创建、更新、删除、恢复文件时的索引回调；删除向量重建端点与托管环境已关闭的 `hybrid_search` 模型工具。已有 `query_files` 工具保留。
- 删除直接依赖和专属测试/启动维护入口；保留数据库检索、安全边界和文件操作的回归。同步 CLI、技能说明和部署说明，避免再承诺语义检索或后台索引。
- 保留旧决策作为历史，保留旧数据库字段、历史工具卡片展示和卷上的所有字节。用户已撤回无损发布要求；云端现有卷继续保留；不删除、压缩、重建向量卷。
- 写入与审核分开：先实现并跑针对性回归，再检查完整调用链与最终 PR 的整体测试；不以删除测试替代保护现存行为。

## Alternatives considered

- 保留依赖，只靠环境变量关闭：最强理由是代码改动小、未来可重新启用；未采用，因为用户明确要求删除，而且数据库检索依然会实例化本地 Chroma。
- 删除所有检索：最强理由是最少保留代码；未采用，因为上下文片段和外部搜索是真实可达行为，用户没有要求删除关键词检索。
- 保留语义工具的空实现：最强理由是旧调用表面不变；未采用，因为没有实际功能却继续给模型一个入口，增加误调用，违背彻底移除的目的。

## Consequences

移除嵌入费用、索引线程和 Chroma 持久卷依赖。数据库检索继续工作；现有向量重建与模型语义工具不再提供。仅移除代码不足以实现 API 无损发布，素材/截图历史引用迁移和云端重叠/退出设置仍需独立验收。
