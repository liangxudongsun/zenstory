# 新注册作者的一次性首部作品与静态引导

## Problem

#181：工作台想法入口要求作者先组织创意；空项目还会自动请求模型建议。默认作品若仅按零项目或浏览器标记创建，会对老账号回填、并发重复、删除补建并污染激活。

## Decision

服务端新增单一 FIRST_WORK_ONBOARDING_ROLLOUT_PERCENT，默认0关闭，非法/越界值也关闭；显式1..100时仅在密码/OAuth真正新建账号时按稳定user id采样，并在同一事务写 WorkspaceOnboarding 资格行。已入资格不因后续比例变化重算，登录与启用不回填旧号。关闭门只暂停新增资格和pending初始化；已初始化作品继续保留静态0模型保护。复用 persona profile 的完成/跳过事实；新资格 pending 且无 profile 时，不让旧七天窗口代替显式完成/跳过。首次正常工作台 POST 初始化复用套餐项目创建 owner gate；项目、现有类型模板目录、一份空正文/剧本文件与结果一次提交，失败全回滚。保存结果原始 id（不做删除级联 FK），明确 skipped_existing；手动/Agent/copy 创建在同一 owner gate 消费资格，硬删除也不重新获资格。

不向 Project 重复加来源列：初始化结果的 project_id 是持久来源关系，文件沿用 JSON metadata 标记 first_work。自动初始化不写 project_created，后台 total_projects 保留全部实际行口径，另以同一聚合快照提供 author_created_projects 与 auto_initialized_projects，明确来源分项且不把自动数当激活；既有正文进度按实际非空字数不计空文件。独立记录真实打开、非空手动保存和额度接受后的主动 AI 时间，不收稿件或提示词。API 建议入口在该作品首次主动 AI 前返回合法空数组，不创建模型服务、不动 AI 用量。静态守卫依据持久原项目仍归作者且存活；删除原始空文件不解除守卫，available 仅表示原文件入口可用。真实打开同样以原项目有效为依据，不要求原文件存在。主动 stream 与自然润色均只在成功预扣后记录首 AI；观测写失败不会中止已获准请求，也不改变模型失败退款。

本 PR 只提供服务端资格、幂等初始化、读取/真实打开接口与模型建议守卫。前端工作台主入口、编辑器静态提示、初次建议加载抑制和聚焦将在依赖 PR 接入；本记录不把尚未接入的用户界面宣称为已交付。

## Alternatives considered

- 复用 localStorage/零活跃项目：最少代码，但跨设备、并发、删除与旧账号边界不成立。
- 在 User/Project/File 各加一套来源和状态：读取直接，但重复事实会漂移；用单表结果关系和已有文件 metadata。
- 注册即建项目或自动示例正文：进入即有内容，但早于验证/偏好且产生未经请求的成本；延迟到引导完成后正常工作台。

## Consequences

新增一张表和迁移（接20261014_090000），无账号回填、无新权益、无模型调用。自动初始化与真实首写分离，真实模型质量和转化仍需后续成熟窗口观察，不用默认作品数量声称成功。服务端和前端分独立依赖 PR 验证，PostgreSQL仅用独占本地合成库。
