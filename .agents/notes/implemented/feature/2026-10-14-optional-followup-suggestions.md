# 写作建议允许有效空结果，不强行补齐

## Problem

#180：独立建议提示要求恰好三条，后端将空列表当作解析失败、少于数量时补齐，前端也把空列表当成网络失败并展示本地备用建议。指定修订完成后仍可能被引向新一批偏好改稿。旧建议规则见 [2026-10-09 记录](../feature/2026-10-09-genre-norms-and-author-voice-suggestions.md)。

## Decision

建议提示改为 0–3 条，优先作者当前目标，完成且没有决策时返回空数组。后端解析用 None 表示错误，[] 表示合法空结果，部分有效建议不再补齐。无模型、超时或非法输出保留原备用建议，不新增调用或重试；生成结果最多三条。API 的 suggestions 数组协议不变。

前端 fetchSuggestions 将 [] 成功与 null 不可用区分，ChatPanel 对有效空结果置 ready、清掉旧芯片并缓存；缓存空数组也是命中，重新打开不再为此请求建议。网络/限流等失败保持备用建议，超时后的合法空结果可以撤掉备用芯片。自动刷新返回后再次核对项目与本次建议key的归属；旧项目结果不能改写新项目的重复回调状态，失败分支同样保存当前真实显示状态。任务实质冲突仍由既有审查/回复传达，不依赖建议数量。

## Alternatives considered

- 用 [] 同时表达错误和无建议：返回类型最简单，但调用方无法判断是否应该填备用建议，仍会覆盖有效空结果。
- 所有失败也不显示备用建议：能完全消掉泛化芯片，但改变无模型/网络失败时的既有体验；本批只去掉对合法结果的强制填充。

## Consequences

完成任务可以自然收尾，打开已确认无建议的项目不多打模型调用。前端返回值新增 null，唯一消费者 ChatPanel 同步更新；HTTP 数组兼容。验证覆盖固定合成输入、mock 生成、API、缓存与显示，不证明模型文风质量、实际返工率或累计费用改善。
