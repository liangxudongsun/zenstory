# 聊天成功文件卡片沿用现有编辑器打开路径

## Problem

成功创建或更新文件的聊天卡片显示文件名，但作者无法从文件名打开正文；手机停留在 AI 页时尤其难以发现已生成的文件。

## Decision

- 只让 `create_file` / `update_file` 成功结果中已有、带非空字符串 ID 的标题成为原生按钮；未完成、失败、仅参数或缺少 ID 的历史记录仍显示文字。
- 从 `ChatPanel` 经 `MessageList` 传递打开回调，复用项目的 `setSelectedItem`；手机沿用文件树的 `switchToEditor`，桌面保持布局。当前项目未确认时不提供回调；旧项目的回调在项目切换后不能继续选中文件。
- 点击已选中的 ID 时保持原 selection 对象，只在手机上切换面板，避免重复加载覆盖只修改标题的草稿。目录保留 `folder` 类型，继续走编辑器已有的目录分支。
- 编辑器继续负责打开失败、切换前保存、同文件 dirty 草稿、版本冲突和流式更新；不通过标题查找文件，不发起生成，不改变聊天滚动、任务或 `edit_file` 的撤销与差异界面。

## Alternatives considered

- **增加查看正文按钮或独立就绪卡片。** 能让动作更醒目，但会重复现有文件名并挤占聊天空间；直接激活已有标题已覆盖同一路径。
- **先查询文件再自行加载正文。** 能提前检查是否存在，但增加另一套打开流程和请求；已有编辑器按 ID 加载并处理失败，复用它可保留草稿保护与并发规则。

## Consequences

作者可用点击、触控、Enter 或空格从现有标题打开准确文件，长标题仍能换行。旧卡片缺少 ID 时不会出现假入口；文件后来删除或失权时由编辑器显示既有错误。打开动作本身不证明文件仍可访问，也不保证独立历史恢复点。
