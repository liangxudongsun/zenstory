# 开写前传入历史篇幅，按作者要求完成后收尾

## Problem

#180：现有篇幅原话提取只在 writer 送审时运行，首次写作输入可能遗漏历史要求，先写短再补。审稿规则把作者明确文风要求与个人审美偏好混在一起，自动审查和返修收尾仍鼓励附一批可选改稿。相关原决定见 [审稿篇幅与交付](../bug-fix/2026-10-11-thinking-loop-contradictory-inputs.md)，独立建议空结果在 [另一小批](2026-10-14-optional-followup-suggestions.md) 处理。

## Decision

首次进入 writer 前复用 _collect_length_requirement_sources、find_length_requirements 和原话格式化；系统提示含历史/项目/本轮原话与来源、先后关系，明确区分全篇/单章/本轮范围，以后说要求为准。本请求内审查与返修复用同一结果；作者原话或 steering 变化时刷新。沿用原有短 session、线程读取和有界超时，不加新模型调用或存储。读取失败仍继续，作者本轮原话仍在正常输入，不声称要求已完整提取。

writer 和 reviewer 共享简短规则：明确的文风、视角、格式和禁止项是交付要求，违反时引用本轮正文的具体证据，只修改授权范围，保留已确认事实与作者手改；个人偏好仍可选。指定修订完成且没有实质冲突/必要决策时直接收尾，可以没有选项。作者明确索要建议或独立审稿仍按要求交付。审稿轮数、只读和版本保护、产物计数、停止保存与费用口径不变。

## Alternatives considered

- 仅改提示文字：没有额外读取，但 writer 依然拿不到已有专门提取的历史篇幅；保留提示改进并把现有提取提前。
- 每次 agent 都重新读历史：始终最新，但重复数据库工作；请求内按作者输入快照复用，追加要求时才刷新。
- 另建要求模型/风格黑名单：可生成结构化评分，但增加模型费用，词语规则也不能可靠判断作者声线；本批只传递明确要求与正文证据，不伪造效果评判。

## Consequences

首次 writer 比以前多一次受限的历史/项目读取，后续送审省掉重复读取。保留原话而不把不同范围的目标合并成单一数字，模型仍需理解范围与最新要求。固定合成数据验证输入链路、最新要求、复用与局部真实写入；这些测试不证明模型会写出更好文风或降低返工成本。真实稿件评阅、连续三章长稿效果、调用次数与含补写的累计费用对照仍需单列预算，不以 prompt 快照宣称完成。
