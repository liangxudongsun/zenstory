# 以 ListenHub 的界面完成度统一 ZenStory

## Problem

用户要求全站质感全面对标 https://listenhub.ai/app/home。实测参考页的侧栏、细描边、克制阴影和内容层次；ZenStory 的创作首页存在灰色面板套灰色输入框、30px/24px 双层圆角与深阴影，非选中胶囊和账户入口有意外描边。ThemeContext 用行内颜色覆盖 CSS，浅色辅助文字、卡片背景和边框与 DESIGN 不一致。页面与控件标题混用衬线，加重了视觉噪声。中文输入法确认和卡片空格键也缺少正确行为；项目卡片把删除和字数说明控件嵌在 role=button 内，语义嵌套使辅助技术无法独立识别。

## Decision

- 在既有 HSL 语义变量上统一浅色白面板/浅灰画布、深色中性墨色、细边框和辅助文字。主题状态只设置 class 与用户强调色，CSS 管理表面与文字。强调色保留用户选择，区分可读的文字/选中态与白字主按钮。
- 控件区域的页面、卡片和弹窗标题统一无衬线；编辑正文保留衬线。原有 DESIGN 的「不做视觉改版」和「控件页面 H1 衬线」被本次用户要求取代，仅对工作台与后台控制界面生效。
- 创作首页使用单层输入面板；类型选择和创建按钮位于同一页脚，手机自然分行。保留原始想法、快捷创建、额度拦截和项目类型记忆。中文组合输入的 Enter 不创建项目。
- 侧栏使用真实链接与当前位置；切换 pathname 重置主区域滚动。手机菜单固定在顶栏下方并独立滚动，正文 inert，关闭菜单保留正文滚动位置。项目卡用原生全卡片打开按钮，删除与字数说明各自是同级操作；原生 Enter/Space 只执行对应操作。复用现有卡片、按钮、搜索、空状态，统一圆角和反馈，保留工作区比例、挂载状态与编辑恢复。
- 复核官网的纸张/墨蓝与真实案例，沿用上一批已经完成的首屏比例与手机案例导航。本批共享样式仅作用于 React 应用；官网、法律与文档页继续使用独立的静态阅读壳。不复制参考站素材、营销数字或工具分类。
- 按桌面、平板、手机，以及浅深色、六种强调色验证真实计算样式、布局与键盘行为。主操作与选中态、辅助文字达到 4.5:1；状态徽章使用独立的文字颜色，危险操作与绿色成功操作使用适合白字的实色。模型、支付和后台写入在浏览器检查中均模拟。

## Alternatives considered

- 完全复制参考站的渐变、搜索和音视频入口能快速接近截图，但会稀释写作入口和已有品牌；借鉴层次与密度，而不移植它的产品结构。
- 只修改首页成本最小，但灰色主题和控件差异会继续出现在技能、素材、订阅、设置和后台；优先修正共享基础，再调整首页。
- 新增设计系统或组件库能规范后续开发，但已有原语足够，且增加依赖与迁移负担；沿用当前组件和 CSS。

## Consequences

收益是全站共享表面、文字和交互层次，创作输入更集中、手机更紧凑。成本是共享主题与原语影响范围较大，已用 317 项组件回归、27 个核心路由/视口组合、后台桌面/手机路由、浅深色、设置与代表弹窗检查覆盖既有页面；视觉质量的「超越」仍需用户判断，测试只证明具体约束。代码仅本地验证与提交，发布另行授权。

本地验证：317 项组件测试、15 项浏览器场景通过（其中含 27 个核心路由/视口组合、六种强调色与浅深色）。lint、CSS token、i18n key、类型检查、完整构建和发布目录生成通过。删除弹窗的颜色检查等待原有入场动画完全结束，避免把透明度混色当作稳定态配色。
