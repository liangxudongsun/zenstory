# Agent Note: 作者手改差异给模型看，edit_file 不再按字符串判断授权

## Problem

2026-10-09 的 P1-3（[agent-respects-author-manual-edits](../bug-fix/2026-10-09-agent-respects-author-manual-edits.md)）：作者把第 3 章「老周」手改成「老秦」，下一轮 AI 写第 4 章时把第 3 章全改了回去。当时的修法是：文件的最新正文是作者写的、作者这一轮的话又没「指向」它时，`edit_file` 整份拒绝。「指向」靠字符串判断：点名加改动动词、上一轮提议加作者答应、正开着加改动……（[author-edit-guard-reads-the-ais-offer](../bug-fix/2026-10-11-author-edit-guard-reads-the-ais-offer.md) 又补了提议解析）。

2026-10-12 生产新用户审计（drama）：作者手改过第 2 集一句台词，然后说「用第二个，顾寒川隔着楼说『曼曼，明天就办完了』那个，直接写进第2集结尾，我那句台词保持我改的版本」。这一轮 0 改动，AI 让作者照念「按这个改，写进第2集结尾」才写入，一个钩子花了 3 条消息。离线重放：整句里有「保持」，提议路径被否决；「写进」不在作者改动动词里。给「写进」做带方向的补丁后，独立复核又找出一串误放行（「你写进第2集的钩子挺好」「不是写进第2集」「你为什么写进第2集」）和漏放行（「直接写进第2集结尾就行了」）。用户否决了这条路：自然语言授权靠枚举动词、正则、否定词判断不了，也不接受模型自报「已授权」这类布尔值。

## Decision

不再判断作者有没有授权修改。把作者具体改了什么交给模型，工程只核对确定的事实。

- **作者改了什么**（`agent/tools/author_changes.py`）：
  - 不加表，不另存差异。在最近 40 个版本的窗口里，按行回放 `FileVersion` 版本链，逐段落记来源。
  - **算 AI**：source=ai；外部 Agent API 的 ai_edit。
  - **算作者**：作者保存、作者恢复、紧跟 AI 写入之后的审阅保存（「AI edit (reviewed)」；不紧跟 AI 写入的，是旧版前端把去AI味审阅也记成了它，算 AI）、系统替作者存下的没进版本的手改（「Before AI edit」等 edit/system）、最新版本之后没进版本的正文。去AI味审阅保存从本批起记作「AI polish (reviewed)」，算 AI。
  - **算原稿**：create 类（导入、新建、上传、快照基线）和快照恢复。
  - 作者写下的段落记下它替换掉的文字：A→B→C 显示 A→C；后来 AI 改别处生成的新版本不会吸收作者早先的手改。自最近一个 AI 版本以来作者删掉的段落也列出。
  - 没有 AI 版本的文件（作者自写、导入原稿）不出差异。窗口截断（即使窗口里没找到手改）、条数截断、回放出错、正文超过 6000 段不回放，都明说「不完整」或「没算出来」，不当作没改过。
  - 只改空白、整段挪位置不算改动；difflib 合成的替换块里被作者删掉的段落也列出。AI 只在作者那一段段尾续写或段首补一句（在句子边界上接）时，那一段仍算作者的。
- **模型在哪里看到**：
  - **工作集旁的 `<author_edits>`**：本轮开始时，对上下文里的文件（焦点、附加、前一章、同级）和跨轮工作集文件计算，最多 30 个文件、整块 3000 字（没核对的文件列出标题）。和工作集一样放在本轮用户消息之前，所有子 agent 都能看到。
  - **`query_files` 按 id 读全文时**：返回里带 `author_edits`。
  - **工作集标签**：原来那句「作者没要求改就别动它」改成指向 `<author_edits>`。
  - **提示词**：作者手改是作者的选择；作者这一轮明确要改时，按新要求改，不再问一遍，也不让作者照念某句话；只有拿不准时才问。
- **edit_file 核对的事实**：
  - **陈旧写入**：`_ReadSnapshots` 记录本请求里模型看到的正文，来源有三处：本轮开始时上下文和工作集里的文件、`query_files` 按 id 读到的（结果被截断的不算）、本请求自己写入的。锁内重读后正文和快照不一致，就拒绝（`stale_content`），列出读过之后的改动，不写库也不重试。改动列全了就把它记成「读到的」，模型基于新正文重发即可；列不全时要求先读全文。
  - **读到的要等模型看到才算**：query_files 读到的、冲突里列出的新正文，从下一次模型调用起（run hooks 的 `on_llm_start`）才算数，并按读库的时刻（不是记下的时刻）和本请求自己的写入排先后。同一条回复里排在后面的 edit_file 是模型看到结果之前写的，仍按旧快照判冲突。换下一个 agent 时清掉读到的（工具结果不跨 agent 回放）。
  - **自己写的立即算、且在提交前记**：PostgreSQL 上提交即放锁，同一文件的下一个并行写入马上在锁内比对；提交失败时还原。
  - **没看过全文的文件**：本请求没看到过全文（上下文全文、按 id 读到、整份写下）的文件，要定位原文的编辑只按逐字匹配；只用 edit_file 往里追加过不算看过。以前近似匹配会命中作者刚改过的句子并静默覆盖，已离线复现：「穿白衣的老人」与「穿黑衣的陌生人」相似度 0.906。看过且没变的文件，逐字 / 忽略标点空白 / 近似匹配照旧。
  - **改到作者的字**：编辑改写或删除了作者写的段落时，结果带 `author_edits_touched`（前后摘录）。判断按段落位置对齐，不看字符串是否出现；只在段尾续写、段首补字不算。工具卡片显示一行「改到了你手动改过的地方」并展开变更详情，撤销沿用原有机制。卡片的「删除」块改为显示实际被替换的原文（`matched_original`），不再显示模型引用的旧写法。
- **删除、递归删除、`create_file` 复用同名剧集整份覆盖**：仍走原来的守卫（`author_edit_guard.py`），放行和保护范围都不变（`latest_text_is_authors` 仍按 change_source=ai 或 change_type=ai_edit 判为 AI 写的，不跟差异计算的归属口径走）。拒绝说明只讲删除和重写：重写被拒时提示要改这一集里的内容就用 edit_file 改具体的地方；删除被拒时提示问作者时点名这个文件（作者回复里要点名并说删）。守卫里只为 edit_file 服务的改名 / 续写放行分支和随 routing 落库的 `author_confirm_file_ids` 已删除。

## Alternatives considered

- **给「写进第N集」加方向判断或更多动词**：改动最小，只碰一个函数。被否决：每补一条规则就冒出新的误放行或漏放行，自然语言覆盖不完。
- **模型自报「作者已授权」再放行**：实现最简单。但这是模型给自己开门，不是可靠的保护。
- **按段落硬拦：改到作者写的段落就拒绝**：最接近 P1-3 的原始意图。可是作者明确要改自己那句时也会被拦，又得回到判断授权。现在改成如实报告，加上可撤销。
- **每轮把全部历史差异塞给模型**：信息最全，但上下文成本无上限。所以限定在上下文和工作集里的文件，并设字数上限。

## Consequences

- drama 原样场景（结尾加钩子、保留作者改的台词）能直接写入，不再要口令。作者明确要把 B 改成 C 时也能直接改。
- P1-3（续写下一章时把作者上一章的改名改回去）现在靠三层防住：模型看到作者具体改了什么，提示词要求保留，改到时卡片如实提示并可撤销。不再有工具层的硬拦。真实模型场景验证见本批的 PR，不承诺所有语义都覆盖。
- 生成期间作者又改了同一文件时，AI 那一步会失败一次，下一步基于新正文改；作者看到的是「这个文件在 AI 读过之后又被改过（多半是你刚改的），AI 没有在旧内容上改，这一步没有改动」，并行卡片里也按「有意没动」显示。
- 本请求没读过就直接改的文件，要求逐字匹配，旧记忆里的写法对不上就会失败，模型需要先读。
- 已知误差：
  - 只看最近 40 个版本（窗口外的手改不列，但会说明没核对完）。
  - 「改到了作者的字」按段落判断：同一段里作者只改了几个字、AI 改了同段另几个字，也会提示。
  - 冲突审阅保存（edit/user）里混有作者接受的 AI 文字，会整体算作作者的。
  - Agent API 在额度满时的写入、edit_file 建版本失败时的写入，都会被当作没进版本的作者正文。
  - AI 把作者的段落挪了位置，会被记成 AI 写的。
