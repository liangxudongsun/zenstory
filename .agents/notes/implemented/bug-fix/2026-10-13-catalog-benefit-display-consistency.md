# 套餐目录补齐版本权益，购买与兑换复用实时拆解次数

## Problem

#189：每文件版本数实际受套餐控制，但公开套餐目录缺字段，定价和账单对比无法显示；付款和积分兑换写死每月 5 次拆解，与可配置套餐发生漂移。英文斜杠单位多出空格。此前 [账单术语决定](../feature/2026-10-08-billing-copy-glossary.md) 已记录写死次数的维护代价，本决定替换该做法。

## Decision

目录的 `file_versions_per_file` 复用实际执行的 `resolve_plan_feature`，包含默认值与合法数据库覆盖。定价、账单与设置复用同一字段和中英文版本单位；前端字段可缺省，在旧 API 发布窗口隐藏缺失权益，不编造默认值。

付款与积分兑换复用既有 `useProMaterialDecompositionsLimit` 和公共目录缓存。只有拿到正数限额才插值展示月度拆解次数；加载中、失败、缺少 Pro 或没有有限正数时省略次数。缓存刷新后两处自动更新，不修改购买/兑换请求。手机英文截图同时复现年付标签换行覆盖购买时长；标签改为卡内正常流，保留两张时长卡的标题对齐，并以真实几何检查避免重叠。英文 `/day`、`/month` 直接连接数值，普通名词单位仍保留空格。

## Alternatives considered

- 在各弹窗同步修改常量：改动少，但后台再调整会重复漂移；使用已有目录查询。
- 目录加载失败时显示默认 5 次：页面完整，但可能对购买者作出不实承诺；暂时省略次数。
- 另建权益接口与缓存：可以单独更新，但已有公共目录足够；复用现有查询，不加依赖。

## Consequences

不改任何配额、计数、价格或订单规则。弹窗首次打开可能短暂没有拆解次数，数据可用后补齐。回归先复现目录缺字段、两个弹窗错误常量、斜杠空格；覆盖目录刷新、失败、中英文及手机/平板/宽屏实际浏览器。真实付款和模型调用均未触发。
