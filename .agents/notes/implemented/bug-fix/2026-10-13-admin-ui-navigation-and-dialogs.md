# 管理后台的导航、阅读与弹窗操作

## Problem

本地虚拟管理员对后台列表、指标、配置页的截图检查发现：未选中的导航被全局边框规则画成胶囊；用户表格状态会拆成竖排；指标卡片显示手型但没有点击动作；手机缺少可见的返回应用入口和菜单内部关闭；切换页面沿用上页滚动位置。辅助文字和部分操作颜色对比度不足，部分横向数据表无法通过键盘滚动。旧的独立弹窗不包含焦点，也不支持 Escape；可见表单标签有未关联输入框的情况。

## Decision

保留六组导航、原有路由、统计口径、权限检查和管理 API。导航改为真实链接，保留嵌套页面的选中态；精简未选中边框和阴影。手机菜单内部有关闭与返回应用入口，打开时隔离背景，复用现有焦点约束；切换 pathname 后清零后台 main 的滚动位置，查询参数变化不触发清零。

后台采用现有 sans 控件标题规范，页面 H1 保留原样。收敛共用面板阴影和指标卡边框，去掉指标的伪点击反馈；时间筛选使用与导航一致的选中 tint。表头和状态徽章保持一行，长用户名和邮箱在自己的列或卡片内换行。后台辅助文字与强调文字采用浅深色可读的颜色，保留当前强调色选择；状态文字复用 success/warning/error-text。手机输入字号至少 16px，主要入口和重试达到 44px。

独立后台弹窗只替换外层 overlay/content 为已有 ui/Modal，保留内部字段、标题、提交回调、条件、错误反馈及按钮的 pending 规则。共享 Modal 支持调用方自带标题的可访问名称与 body 间距覆盖。提交期间不能 Escape 关闭；原本不能点背景关闭的弹窗继续如此。具有背景关闭行为的审核原因框保留该行为。焦点约束、返回触发点和滚动锁由已有公共实现承担。

## Alternatives considered

- 为后台建立另一套卡片、表格和弹窗体系可以彻底统一样式，但会扩大迁移和业务回归范围；本次复用已有 HSL、按钮、Modal 与数据状态组件。
- 只改字体和边框改动更少，但不能解决键盘、触控和表单关联问题；纳入已复现的交互缺陷。
- 在每个旧弹窗分别添加 Escape 和焦点监听，可保持原 markup，但会复制公共实现及 pending 规则；替换包装并保留调用方内容更容易验证。

## Consequences

后台更容易辨认选中页面和操作状态，手机有明确返回路径，键盘可以完成菜单、表单和弹窗操作。Portal 弹窗显式继承后台阅读样式。使用本地合成数据验证，没有修改真实用户、套餐、订单、积分或配额；没有部署。组件回归、管理操作生命周期、浏览器路由、手机弹窗、浅深色可访问性、lint/typecheck/build 作为本批验收。灵感模块保持默认关闭，在独立本地测试实例开启该开关验证编辑和审核；测试按路由可用性执行，不改变常规或 hosted 环境开关。
