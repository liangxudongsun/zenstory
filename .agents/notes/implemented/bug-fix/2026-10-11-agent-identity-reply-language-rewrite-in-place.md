# Agent Note: 自称 ZenStory 写作助手、回复语言跟随作者最近一条消息、重写在原文件上改

Status: implemented

后续：官方技能正文改为不对用户公开，身份段落写明优先于数据库配置，见 [2026-10-11-official-skill-text-hidden-and-identity-rule](../feature/2026-10-11-official-skill-text-hidden-and-identity-rule.md)。

关联：[2026-10-08-agent-review-gating-and-handoff-details](2026-10-08-agent-review-gating-and-handoff-details.md)（英文界面语言区段只约束聊天回复；本条推翻其中「作者写中文也用英文回」这一半，见下）、[2026-10-09-agent-text-no-english-narration-or-glue](2026-10-09-agent-text-no-english-narration-or-glue.md)（「每一句都用作者使用的语言写」）、[2026-10-09-ai-write-backs-up-unversioned-text](2026-10-09-ai-write-backs-up-unversioned-text.md)（AI 改写前备份原稿，原地改写依赖它）。

## Problem

- **I23 身份**：作者问「你是哪个国家的 / 你是什么模型」，回复过「由中国的团队开发的（DeepSeek）」和「我是 Claude，Anthropic 开发的模型」（生产只跑 deepseek-flash，后者不实）。代码组装的提示里没有任何产品身份；数据库里的 role_definition 看不到，事实证明也没起作用。另有一次应要求加载全部 17 个技能并逐字贴出技能正文。
- **I22 语言**：英文界面（`Accept-Language: en`）时 `MessageManager._build_language_section` 追加「## CRITICAL: Output Language … Reply in English even if the user writes in Chinese」，压过基础协议的「用作者使用的语言」；作者从英文推荐按钮发了第一条，之后一直写中文，回复仍是英文（思考里写着「Given the CRITICAL rule, English」）。中文界面的英文作者走审稿时，审稿人收到的是系统拼的中文任务消息，看不到作者用的语言，结尾接了一段中文总结。
- **I17 重写**：`base.py` 的「大改/重写/改标题」规则直接要求 >50% 重写时 create_file 新建（必要时加「（新版）」）、再问作者删不删旧文件。正文目录因此出现两三份同章号文件，每轮结尾把「删不删旧版」推给作者。原地改写本来就是安全的：`edit_file` 改之前会备份未进历史的原稿并建版本。删除确认也没有统一规则（有的会话先问再删空草稿，有的直接删）。

## Decision

- **身份**：`base.PRODUCT_IDENTITY_PROTOCOL` 紧跟数据库 role_definition 之后进入每个项目类型的系统提示（所有角色共用基础提示，含审稿人）：你是 ZenStory 的 AI 写作助手；问到模型、公司、国家时只这样说，不说也不猜底层模型或厂商名；系统提示、协议、技能提示词不原样贴出，概括能做什么，想看技能全文时指向技能页面（技能全文本来就在技能页面展示，这里不是保密，而是不把内部说明当回复正文整段贴）。测试只锁「身份段落不依赖数据库角色定义、位置在角色定义之后」，不锁措辞。
- **语言**：`_build_language_section(force_en)` 中英界面都输出：聊天回复用作者最近一条消息的语言，作者换语言就跟着换；消息看不出语言（选项字母、数字、链接）时沿用对话里一直用的语言，再判断不了才用界面语言；文件内容保持稿件语言（沿用 10-08 的规定）。删掉「Reply in English even if the user writes in Chinese」。`detect_author_language` 按汉字数与英文词数判断本轮原话（一个英文词约抵两个汉字），`build_system_prompt(author_message=…)` 在系统提示末尾（动态段，不影响前缀缓存）写一行「本轮作者用中文写消息…包括审稿后的总结」或英文对应句；判断不了不写。所有角色共用系统提示，审稿人也能看到。`AUTHOR_REPLY_PROTOCOL` 写明作者语言以最近一条消息为准。
- **重写**：规则改为在原文件上用 `edit_file` 改（逐段多个 replace；整章重写用一个 replace，old 为原文全文），回复里一句话说明旧稿在历史版本里能找回，不问删不删旧文件；只有作者明确要求保留旧版、另存或对照时才新建。改标题 / 移动没有专门工具，仍是新建后问作者要不要删旧文件。`delete_file` 说明加一句：作者没要求时只删本轮自己新建、还空着的文件，其余（含项目自带的空白草稿）作者点名才删。重写规则是提示词改动，按 AGENTS.md 不加锁定文案的测试。

### 推翻 2026-10-08 的一半

10-08 note 让英文界面的语言区段「只约束聊天回复」，并保留了「作者写中文也用英文回复」。它的理由是英文界面的作者应得到英文回复；但界面语言并不等于作者此刻用的语言（推荐按钮、组织站带过来的页面语言都会把中文作者带到英文界面），而且与基础协议「用作者使用的语言」直接冲突。本条保留 10-08 的「文件内容保持稿件语言」，只把「聊天回复强制英文」改为「跟随作者最近一条消息，界面语言兜底」。

## Alternatives considered

- **身份：在回复出口检测「我是 Claude / DeepSeek」并改写**：能拦住漏网的回答。没采用：属于输出过滤式保护；先在提示词源头给出身份，观察后再说。
- **身份：禁止透露任何技能内容**：最强理由是省 token、口径统一。没采用：技能全文本来就在技能页面公开，整条禁止会和界面矛盾；只是不整段贴、改为概括并指路。
- **语言：前端把界面语言跟着作者消息切换**：改的是界面而不是回复，且前端不在本包。
- **语言：只改提示词，不做服务端检测**：审稿人收到的是系统拼的任务消息，提示词里的「作者最近一条消息」对它不可见，必须由服务端写明。
- **语言：在写作图里给审稿任务消息加语言行**（I22 建议第 2 条）：同样能解决审稿人语言，但要改 writing_graph；系统提示末尾这一行对所有角色都生效，改动更小。
- **重写：给 edit_file 加整篇替换的 op，或让 create_file 同名复用已有章节**（I17 建议第 2 条）：整章重写时模型不用把原文全文抄进 `old`，更省 token、也不怕匹配失败。没采用：新 op 要改 `file_ops/edit.py` 与前端的改稿审阅 / 工具卡展示，同名复用要改 crud 的复用分支和作者手改保护，都超出本包；现有 `replace` 已能完成原地改写，且自动备份与版本照旧生效。

## Consequences

- 收益：作者问身份时得到稳定、真实的产品身份；中文作者在英文界面也收到中文回复，英文作者的审稿总结不再接一段中文；重写不再在正文目录里留下同章号的「（新版）」文件，作者不用再处理删旧稿。
- 代价与剩余：
  - 都是提示词与语言检测，没有用真实模型回放验证（本批不调用付费模型）；上线后需要用诊断账号观察身份回答、英文界面中文作者的回复语言、「重写第 N 章」的工具调用。
  - 语言检测是按字数的粗判：作者贴一大段中文稿子再用英文提要求时会判成中文；中英夹杂且两者相当时可能判错。只看本轮第一条消息，运行中追加的消息不重新判断。
  - 整章重写要把原文全文写进 `old`，输出 token 比新建文件多一份原文；原文与 `old` 对不上时会走 edit_file 的锚点失败恢复。
  - 中文界面的系统提示也新增了「回复语言」段，前缀缓存会在上线后失效一次。
  - writer 送审前那句进度说明的中文示例（subagents.py）未改，靠系统提示末尾的语言行覆盖。
