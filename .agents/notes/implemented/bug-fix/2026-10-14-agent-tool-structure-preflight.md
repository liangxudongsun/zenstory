# Agent 工具派发前校验与任务板规则提示

## Problem

`parallel_execute` 的 schema 虽要求 type，但模型参数不启用严格 JSON schema。缺字段或非法类型会在部分合法任务已执行后逐项失败、发进度并记录 traceback。任务板单一 in_progress 规则只在校验器出现，被拒后模型不知道怎样修正。对应 #195。

## Decision

并行工具在截断和任何子任务派发之前，检查完整请求中每项的 type。发现首个缺失、非法或非对象子任务时返回一条含下标、合法枚举、示例与整批未执行说明的错误，只记一次 WARNING，不发并行进度，不推断任务类型。合法批次的并发、数量上限、结果与文件保护规则不变。update_project 的工具、tasks 和 status 描述写明最多一个 in_progress、其他未开始项为 pending；拒绝信息说明当前数量及重新提交完整 tasks 的修正方法。

## Alternatives considered

- 依据 params.edits 推断 edit_file：能省去一次模型修正，但错误结构可能被转成真实写入；不替模型猜测有副作用的操作。
- 全部工具改用严格 schema：能统一提前发现参数问题，但影响动态参数与所有工具兼容性；本批只修有生产证据的派发边界。

## Consequences

避免同批部分执行后才报告结构错误，减少逐项失败与无意义进度。一次非法输入仍是一条正常工具拒绝，现有熔断器与费用规则不变。模型需修正后主动重发，不自动重试。
