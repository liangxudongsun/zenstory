# Agent Note: 停止字数等待残稿补存回执

## Problem

PR175 的本地真实 DeepSeek 测试中，收到 716 字符流式正文后主动停止。done 与历史都说保存 585 字，实际文件及版本保存 748 字符、611 字。StreamProcessor 为控制标记保留的尾部缓冲在取消时补存，但没有作为 SSE 帧发出；只累计帧的 RoundWrittenFiles 漏掉尾部。

关联决策：[停止后列文件](../../implemented/bug-fix/2026-10-11-new-chat-mid-round-stop-and-written-files.md)、[停止产出与终态](../../implemented/architecture/2026-10-09-stop-output-definition-and-round-outcome.md)。

## Decision

每轮 adapter 现在保留本轮取消补存任务和最终正文计数回执；部分历史收尾先等待该任务完成，再交回助手消息 id。成功补存的实际字数覆盖帧累计字数，done 与历史共用回执；等待消息 id 超时时，实时提示省略字数。仍不重读数据库、不重试模型、保留原停止计费与截断覆盖保护。

范围限于取消补存、字数回执、对应回归和真实停止复测，不改生成路由与发布配置。

## Alternatives considered

- 从数据库直接读正文：能得到最新计数，但补存尚未落定时读到空文件，而且可能把作者并发修改也算成这一轮所写。保留旧决策的拒绝理由，使用当前轮保存任务的回执。
- 继续累计 SSE：轻量且已覆盖正常流，但取消清理阶段不能继续 yield，尾部缓冲仍会遗漏。
- 停止时丢掉尾部缓冲：界面计数与落库一致，但损失已生成的正文，不采用。

## Consequences

补存慢时停止的消息 id 可能稍晚，现有超时边界保留；实时超时省略字数，刷新后由终态展示保存回执。所有作品与凭据均为本地测试，凭据和原始收据不进入 Git。
