# 已删除文件的编辑终态与草稿保留

## Problem

#190：Agent 删除当前打开文件后，编辑器把 404 作为暂时错误重试并显示无法成功的载入按钮。静默文件树刷新也没有校正选择；直接 delete_file 生产结果只含布尔值，无法靠工具结果定位被删 id。直接取消选择还可能丢掉未保存或比较中的正文。

## Decision

删除结果有 id 时立即通知；旧布尔结果和 parallel_execute 用成功的新文件树验证当前选择。树刷新只校正请求发起时仍打开且此前已知的节点，失败、过期或项目切换响应不作为删除证据。Editor 把 404 视为终态，同步保留 dirty/比较草稿后清理选择和 last-open；草稿按原 user/project/file 隔离，保留查看与下载入口。持久化失败保留内存并明确说明；通过 beforeunload、chunk 刷新拦截与既有唯一离开确认保护内存稿，不再向已删除 id 自动保存。过期读写响应不能覆盖新的选择。

## Alternatives considered

- 只取消选择最少代码，但卸载保存会继续 PUT 已删除文件且恢复入口不可达；不采用。
- 修改后端 delete_file 返回协议能携带所有 id，但旧服务与文件夹删除仍须树/404兜底；本批在前端统一收敛，不扩大协议。

## Consequences

终态不重试、不显示网络恢复误导。未保存正文不自动覆盖任何新文件。增加按用户与项目展示删除草稿的入口，存储失败仍须作者下载副本后再离开。

## Verification

新增四项删除/404/dirty/存储失败回归先失败后通过；晚到 PUT 的统计回归和手机树删除回归也先失败后修复。最终 382 项受影响单测通过，覆盖旧布尔与并行删除、删除包含当前文件的目录、晚到 GET/PUT、按用户项目隔离、硬刷新前已留草稿和 storage 失败。390px 与 1280px 的真实 Chrome mocked SSE 回归均通过，下载文件逐字节等于标题与 dirty 正文，删除后没有额外 GET 或 PUT。完整 typecheck/build、ESLint、token/i18n 检查通过；未调用真实模型或修改云端。
