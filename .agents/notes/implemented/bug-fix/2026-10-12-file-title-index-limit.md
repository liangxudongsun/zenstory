# 文件标题超长导致 PostgreSQL 500

## Problem

生产日志显示浏览器 POST 文件端点把几千字文字放进 title、content 为空；ix_file_title 的 B-tree 项超过页限制。日志不能证明 Agent 传参错误；内部 Agent 写文件不走此 HTTP 端点。所有入口缺少标题上限。

## Decision

标题限制为 255 个 Unicode 字符，最坏 UTF-8 编码 1020 字节，保留现有索引与数据库结构。浏览器和外部 Agent API 请求模型先拒绝超长输入；内部 Agent 工具在任何写入前校验并给出明确错误。前端创建/改名提示上限并保留原输入，不截断，不猜测正文去向。长正文仍允许存入 content。

## Alternatives considered

- 删除标题索引：能让任意长字符串写入，但没有解决正文误放标题的输入问题，也影响既有标题查询；本轮不改数据库索引。
- 自动取首行或截断并移到正文：体验看似顺滑，却擅自改写用户意图和内容；不采用。

## Consequences

错误在写库前变为可纠正的校验失败，不发生内容截断。历史标题不回写；仅编辑正文仍应允许历史文件保存。

## 后续修正（本批复核）

- 生产有 3 个未删除文件的标题超过 255（最长 546）。编辑器自动保存总带上未改的标题，`FileUpdate` 又在字段上限长，这些文件只改正文也存不了。现在编辑器遇到未改名、且已超上限的历史标题时不重发 `title`（其余保存照旧带完整标题快照，AI 改名与排队改名的同步不变）；网页与外部 Agent API 的 PUT 只在标题确实改变时检查上限。
- 在编辑器标题栏改出超长标题时，同一个标题提示一次 `editor:fileTree.titleTooLong`，标题与正文原样留在编辑器。
- 素材导入的 `file_name`（含建议名）同样检查上限。
