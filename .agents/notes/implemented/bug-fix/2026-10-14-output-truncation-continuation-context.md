# 截断后的继续携带事实，重复截断建议缩小请求

## Problem

#196：只有思考的 output_truncated 轮次虽然已保存 stop_reason，思考不回放后没有可见文本，模型历史会丢掉整轮；下一轮「继续」不知道该步骤没有交付。原文案还承诺继续就能完成。此前根因与不限制 effort/思考长度的决定见 [2026-10-11 记录](2026-10-11-thinking-loop-contradictory-inputs.md)。

## Decision

复用持久化的 assistant stop_reason，在 SDK 回放中合成一行 [output_truncated] 事实，不保存或回放思考、不把说明写成作者原话。只有现有路由已判定为 output_truncated 后的显式继续，才在本轮系统提示追加简短引导：直接动手，任务大时先交付范围内第一部分并说明剩余。其余可继续的停止原因保留原路由与提示。

连续截断次数只从历史 assistant stop_reason 读取，遇到其他停止原因归零，并在同请求的多 agent 间保留这份请求开始时的计数；不根据显示文字或用户输入猜测截断。连续第二次及以后使用独立错误码的中英文缩小范围提示；首次文案允许再尝试但不保证完成。维持 retryable=false，沿用现有按真实产出返还的规则，不自动重发、不变更模型 effort、输出预算或审稿轮数。

## Alternatives considered

- 新增数据库截断字段或复制 status card：能独立计数，但已有 stop_reason 是持久化事实，投影一行模型历史就能防止该轮消失；新增存储字段与可见状态卡会重复状态来源。
- 截断后自动重试或降低思考上限：能自动恢复或缩短等待，但违反现有决定，仍可能重复收费或改变质量；作者继续保持显式操作。

## Consequences

模型能看到上一轮没交付的事实，重复停止的文案不再作完成承诺。回放只多一行简短说明；计数以当前加载的历史窗口为限，重复分类只需上一条已保存的助手终态。模型质量、真实重复截断率及累计费用未通过付费模型验证；上线后的 stop_reason 序列观察仍是单独验证事项。
