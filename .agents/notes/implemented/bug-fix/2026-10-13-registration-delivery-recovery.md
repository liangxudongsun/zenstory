# 注册验证码投递失败与未验证邮箱恢复

## Problem

注册先提交用户、邀请和权益，再发送验证码。Resend 拒收 `to` 时，用户和用户名已经占用；临时失败与永久地址错误混在一起，页面仍声称验证码已发送。历史未验证账号也缺少保留用户名的纠错入口。

## Decision

- 在 EmailStr/IDNA 校验之后检查 ASCII 顶级标签，仅拒绝含数字的普通 ASCII 标签，保留已经验证过的 `xn--` IDN；投递时使用 email-validator 的 ASCII 域名表示，不执行 DNS 查询或实际邮件验证。
- 注册先 flush 预留唯一约束，发送后再首次提交。只有 SDK 的 400/422 `validation_error` 且明确 `Invalid \`to\` field` 才回滚新用户并返回专用本地化错误。发送方配置、限流、超时和其他错误保留未验证账号，返回 `verification_sent=false`，前后端均不声称邮件已发出；不自动重试邮件。
- 增加密码证明的未验证邮箱纠错入口，要求账号 active、未验证且注册密码正确。失败统一凭据错误并按 IP/邮箱限流，不修改密码、不删除已有账号/关联记录、不签发登录令牌。发送失败保留旧地址；成功保留账号 ID 和用户名，撤销旧地址验证码。
- 邮箱验证与纠错共用刷新身份映射的 User 行锁，等待移到线程，防止并发旧验证码验证新地址。旧地址验证码和冷却状态必须在仍持有地址唯一性事务时失效，随后才提交释放地址；清理失败回滚纠错并返回可重试错误。新注册在 flush 取得地址之后、首次发码之前失效该地址的孤立状态，清理不可用时不提交新账号，防止继承前任账号验证码。永久收件地址拒绝后的清理错误只记警告，不掩盖专用地址错误。
- 保留 [认证阻塞调用移出事件循环](../../implemented/bug-fix/2026-10-05-auth-blocking-calls-off-event-loop.md) 的执行约束。真实一次性 PostgreSQL 测试观察 `pg_blocking_pids`，覆盖纠错先提交与验证先提交；接入既有串行 PG CI lane。

## Alternatives considered

- **删除已提交的未验证账号**：能立即释放用户名，但会触碰邀请、权益、使用记录等关联数据，旧账号也可能已有内容，因此拒绝。只回滚本次尚未提交的用户。
- **顶级域名仅允许 `[a-z]+`**：能拦住 c0m 手误，但会误拒合法 IDN，因此先使用已有 IDNA 校验结果，不新增域名清单或 DNS 依赖。
- **把所有 ValidationError 都当地址错误**：实现简单，但发送方未验证、API 配置和权限也使用该错误类型，会误导用户并错误回滚账号，因此只识别明确的收件字段拒绝。
- **仅提供重新注册链接**：不需要新增接口，但历史账号仍占用原用户名，无法实现恢复；以密码证明纠错并保持未验证状态。

## Consequences

注册在首次提交前会等待一次有界邮件请求，唯一约束等待通过线程执行。有效语法不保证最终送达，未知投递错误按保守的可重试状态处理。纠错只服务尚未验证的密码账号，已验证账号换邮箱、OAuth 策略和自动清理账号均不扩展。
