# 免费版每日次数以代码策略为准

## Problem

#187：免费每日次数由代码固定为三条，但后台原始 JSON 编辑允许保存其他数字，产生「修改成功却不生效」的误解。承接[三条策略](../../implemented/feature/2026-10-13-free-ai-three-per-day.md)与[有效权益卡片](../../implemented/bug-fix/2026-10-13-admin-plan-card-effective-entitlements.md)。

## Decision

遵守现行三条产品约束，保留代码为免费每日次数权威来源。后台把此键从 JSON 编辑区移到只读字段，并解释需要代码发布才能调整；粘贴不同值时阻止提交。服务端拒绝非三条的显式修改且不写审计或其他字段；修改其余免费权益时落库存储值三条。Pro 与自定义套餐仍照存储配置执行，不改预扣、返还、重置或已用次数。

## Alternatives considered

- 改为数据库权威能支持运营即时调额，也减少部署顺序差异；但会让后台覆盖当前明确的三条规则，并改变回滚和配置权限语义。本批选择明确不可编辑，数据权威可另行授权改变。
- 只加提示而继续接受无效值改动最少；但接口仍声称保存成功，脚本也可继续写入，不能解决管理预期。

## Consequences

不需迁移或生产写入即可禁止新漂移；已有旧行仍按代码三条执行，在下一次合法编辑时规范化。管理端与服务端均需回归，已有额度与接口一致性测试继续验证。

## Verification

新增回归改前为 5 项服务端失败与 2 项界面失败，明确复现了无效修改被接受和缺少只读说明。修改后相关后端 47 项与前端 11 项通过，覆盖旧数据库 daily=10、不可修改、其他套餐可编辑、合法保存规范化，以及原有扣次/返还/日界行为。TypeScript 与完整前端构建、ESLint、token/i18n 检查和 Ruff 通过。没有生产数据写入。
