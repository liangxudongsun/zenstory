# Agent Note: 审稿总结核对其他章节当前版本

## Problem

本地真实模型测试：第二章从第三人称重写成第一人称，再由作者在历史版本界面恢复原稿。UI、数据库与 SHA256 都证明已恢复第三人称。随后只写第四章，审稿总结却顺带说「第二章仍是第一人称」——沿用了旧回复中的状态。

关联：[回复总结与真实字数](../../implemented/bug-fix/2026-10-11-author-reply-single-summary-and-real-word-counts.md)、[完成声明采用提示规则](../../implemented/bug-fix/2026-10-11-file-stream-continuation-and-truthful-completion.md)。前端只传焦点 id，服务端从数据库读当前正文；不改版本恢复与上下文装载。

## Decision

质量审稿人写总结时，其他章节的人称、内容、版本也须从本轮当前正文核对；历史「已改」不是现在状态。未核对的其他章节不附带断言。已用真实「恢复后查现稿／复审当前章节」验证，不添加匹配字词的输出拦截。

## Alternatives considered

- 在服务端识别人称声明并覆盖模型回复：可强制更正这条错误，但无法泛化到其他文件状态，且负责人已选择以提示规则约束完成声明，保留该决策。
- 每次审稿把所有章节都注入：更容易看到最新文本，但大项目占满上下文且增加成本，仍无法保证模型遵循，不采用。
- 只记录问题：模型偶发错误不能完全消除，但当前规则只强调本轮改动，补一句其他章节现状的核对要求有明确针对性。

## Consequences

减少历史状态被误述为现状的风险；仍属于模型软约束，真实复测通过不等于以后绝不会误述。测试数据为本地虚构作品，没有生产作品或凭据进入 Git。

## Verification

- 修改前真实审稿误说第二章仍是第一人称；旧稿恢复后内容 SHA256 与原第三人称稿逐字一致。
- 修改后真实复审读取第二、四章，准确报告第二章当前为第三人称，并明确历史版本本轮未核对；没有修改章节。实际发送给模型的提示包含新规则。
- 子角色提示、收敛与跨轮工作集相关 46 项通过。该提示为软约束：还观察到建议芯片提出把已经是第三人称的第二章「统一成第三人称」，但其输入已包含当前正确回复，是模型的冗余建议，未引入文本过滤或额外规则。
