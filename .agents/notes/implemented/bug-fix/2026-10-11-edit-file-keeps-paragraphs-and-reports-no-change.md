# Agent Note: edit_file 不并段、插入守住句子与段落边界、没改动就如实报错

Status: implemented

相关：边缘标点扩展与整批回滚见 `2026-10-08-agent-edit-file-silent-corruption.md`，匹配守卫见 `2026-07-18-agent-edit-safety-guards.md`，这两处的规则本笔记不改。引号规范化见 `../feature/2026-10-09-agent-writes-normalize-cjk-quotes.md`，本笔记只补一条「只改引号」的例外（见 Decision 第 4 点），原有规则不变。

## Problem

2026-10-11 审计 I10：10-08 的边缘标点修复之后，edit_file 仍有几条路径「报告成功，正文却被改坏或根本没变」。

- **并段（U068，10-09）**：`normalize_for_fuzzy_match` 把换行和其他空白一起去掉，单行的 old（「……站了一会儿。他数了数……」）在归一化空间里和「上一段段尾 + 下一段段首」连成一处命中。命中范围里含 `\n\n　　`，替换成不带换行的 new 后两段并成一行，下一段的「　　」接在上一段句号后面。审稿一次找出 14 处。
- **插入不认段落边界**：insert_after/insert_before/append/prepend 把 text 原样塞进定位点。整段文字插在段尾却没以换行开头，就接在上一段行尾；插在段首（下一段缩进之前）却没以换行结尾，下一段的缩进就跟在新段落行尾。
- **插在字和标点之间**：锚点停在「一会儿」而原文是「一会儿。」，插入一整句得到「一会儿他喘了口气。。」。近似匹配的锚点窗口更常停在句子中间。近似 replace 的窗口停在句中时，替换后留下半句残尾（「风停了。一本很旧很旧的书。」）。
- **没改却报成功（U079，10-10）**：「」体例的稿件里把对白改成 “”，模型在 new 里写半角 `"`，规范化器按稿件体例又写回「」，正文一字没变。每条仍记进 applied，结果是 `edits_applied=9`、`mutation_applied=true`，实际只改了一处。

U092（前半篇整段消失）的写入者是流式整篇写入或编辑器保存，不在 edit_file 里，本包不处理（见 Consequences）。

## Decision

1. **replace/delete 的模糊、近似匹配不跨段落分隔。**
   - `text_matching._line_break_before` 记下每个归一化字符和前一个之间是否隔着换行。
   - `find_fuzzy_spans(keep_line_breaks=True)`：原文在命中范围内的每一处换行，pattern 在同一归一化位置也必须有，否则这个候选作废，计入 `stats["paragraph_rejected"]`。
   - `find_approximate_match(keep_line_breaks=True)`：近似窗口不逐字对齐，所以按数量约束：窗口内部的原文换行数不能多于 pattern 自己的换行数。不合格的窗口不参与选最佳和歧义判断，但记下其中最高的相似度。这个分数不低于段内最好的窗口时，整次近似匹配放弃（返回 None，`paragraph_rejected` 照常计数）。原因：改写过的单行 old 盖住「上一段段尾 + 下一段大半」时，下一段里的段内窗口也能过 0.75 阈值，可它只是跨段那处的一部分。拿它去替换，new 里属于上一段的内容（「嗡嗡作响。」）会再写一遍，比并段更难发现（复审发现）。
   - `edit._apply_replace` 和 `_apply_delete` 开启这一约束。所有候选都因跨段被排除，或近似匹配因上一条放弃时，直接报 `anchor_not_found`，并说明「old 里缺那处换行，请照抄原文的换行和段首缩进，或拆成每段一条 edit」，不再退到近似匹配。原因是近似匹配可能只改其中一段的局部，把另一段的开头重复写一遍。还有其他命中时，在 warnings 里说明排除了几处。
   - insert_* 的锚点定位不加这条约束：锚点跨段不会让插入并段，加了只会多出定位失败。
2. **插入点对齐句子边界**（`paragraph_layout.is_sentence_shaped / is_sentence_boundary / snap_to_sentence_boundary`）。
   - text 是一整句（以句末标点收尾，可带闭引号），或带换行、带段首缩进时，insert_after 落在句子中间就往后挪到这句话结束，insert_before 就往前挪到这句话开头。
   - 句末标点和它后面的闭引号属于前一句，所以「冰|。」「冰。|”」都不是边界。
   - 以逗号、句号、闭引号开头的分句（「，腿有些发麻」）原样贴着锚点，这是原有的行为。
   - 引语和打断的话也是边界：句末或冒号后面的开引号，引号前后都算句首（「说：|“|我们」），句子中间的引号（「看着“老王”」）不算；「“你——”|他」算一句结束。
   - exact（含引号等价）命中的锚点，模型看得见它的边缘，只在插入点把一个字和它的标点、或半句话的两半分开时才挪（`exact_anchor_snap_forward`：锚点外侧的那个字是字母或汉字，比如「一会儿|。」「他转身|走了」）。锚点边缘是标点（引号、冒号、破折号、逗号、句号）时原样插入，这就是模型选的位置：引语里、冒号后、打断的话后。第一版对 exact 也一律挪，结果把引语里的一句挪到说话人前面当旁白，把冒号后的新引语挪进了原引语里（复审发现）。
   - 模糊、近似、fuzzy_paragraph 的窗口边缘是猜出来的，照常挪到最近的句子边界。append/prepend 本来就在文件两端，不需要挪。
3. **段落边界上的插入用文件自己的分段与缩进**（`paragraph_layout.layout_insertion`，四种插入 op 都用）。
   - 适用条件：插入点在段尾、段首（含段首缩进的前后）或两段之间，并且 text 带分段标记：以换行开头、以段首缩进开头（全角空格、制表符或两个以上半角空格）、以换行结尾。在段首或两段之间时，text 中间有换行也算。
   - 分隔：去掉 text 首尾的空行，插到上一段文字末尾，前面补插入点处原有的那串换行，后面接着原有的分隔。两段之间是 `\n` 就用 `\n`，是 `\n\n` 就用 `\n\n`。
   - 缩进：前后两段的缩进相同时，给新段落里没有缩进、以文字或开引号开头的行补上。章节/分集标题行（「第31章 …」「第五集」「Chapter 3」、markdown 标题；「第三部电影…」这类正文不算）不套正文缩进，跟本文已有标题的缩进走：本文标题顶格或没有标题时顶格（`paragraph_layout._HEADING_LINE`，回归用例在 `test_edit_file_paragraph_integrity.py`）。
   - 文件开头：在第一行前插入，后面补全文最常见的分隔。
   - 文件末尾：保留模型自己写的结尾。前文没以换行收尾时，只有 text 以换行或段首缩进开头，才在前面补全文最常见的分隔、给第一行补缩进；text 只是以换行结尾的，第一行接在行尾，后面各行照常补缩进。原因：续写被截断的半句（「桌上放着一封」+「没拆的信。\n\n　　他走过去。\n」）或分块追加时，结尾的换行只说明下一块从新行开始，不说明这块要另起一段。第一版把结尾换行也当作分段标记，把半句话从中间拆成两段（复审发现）。
   - 不带任何分段标记的一句话仍接在段尾或段首，只是不会夹在段首缩进前面，也不会夹在两段中间的空行里。段落中间以换行开头的插入（模型就是要在这里拆段）原样执行。
   - 调整过的地方在 detail 里写 `layout_notes`。`text_preview`/`text_len` 记的是实际写入的文本。
4. **报告成功就必须真的改了。**
   - `_edit_file_impl` 在每条编辑前后比较正文。没有变化时撤回这条的 applied 记录，抛 `EditFileError(error_type="no_change")`（新增 `EDIT_ERROR_NO_CHANGE`）。它和其他失败一样走整批回滚，或在 `continue_on_error=true` 时进 `failed_edits`，不计入 `edits_applied`。new 里有半角引号时，错误会说明「统一成全角后与原文一致」。`user_message` 用通用说法，不新增文案。
   - 根因修法：`_apply_replace` 里，old 和 new 只差引号写法（`fold_double_quotes(old) == fold_double_quotes(new)` 且两者不同）时，这条编辑就是在要求换体例。new 里的半角引号按产品默认的 “” 写入，不再按稿件体例写回「」。new 里直接写的「」/“” 原样保留。改了字的编辑仍按稿件体例规范化。
5. `EDIT_FILE_TOOL` 的 `old`、`text` 描述各加一句，说明跨段要照抄换行，以及段落插入会按本文分隔补齐。
6. **模糊 / 近似 replace 的 new 按原文这一段的段首缩进写**（`paragraph_layout.follow_span_indentation`，live run 2 场景 C 补充）。原文段落没有缩进，模型写的 old 却带「　　」；匹配时空白被忽略，照样命中，new 也带着「　　」写进去，一章从 1 段有缩进变成 10 段，AI 还把这说成原有状态。规则：只看段首行（命中范围里换行之后的行，第一行只在命中从行首开始时算）。原文这些行只有一种缩进 X、old 对应行也只有一种 Y 时，new 里缩进是 Y 的段首行改成 X。原文没缩进就去掉 new 的缩进，反过来也一样；命中从原文缩进之后开始时不叠两层。原文或 old 自己就混用、从句中间开始的命中、标题行都不动。exact（含引号等价）命中照旧逐字写入。改过时 detail 里写 `layout_notes`。按场景 C 的原文重放：改前 10 段带缩进，改后 1 段（作者自己那句，走的是 exact）。

## Alternatives considered

- **跨段命中时把原文的 `\n\n　　` 按位置映射回 new**（审计建议的另一种做法）。最强理由：模型不用重发，一次就改成。被否：new 是改写后的文本，和 old 没有逐字对齐，「同一位置」只能猜。猜错了，换行就会插进句子中间，或者落在改写后另一个分句的后面，那是另一种破坏。拒绝并说明缺了哪处换行，模型下一次就能照抄。
- **规定 insert 的 text 必须以换行开头，否则报错**。最强理由：规则最简单，不用推断。被否：很多插入本来就是接在段尾的一句话，强制换行会把续写也拆成新段。缺的换行在文件里有现成的样子可以照用，报错只会多跑一轮。
- **近似 replace 的窗口停在句中时，自动扩到整句**。最强理由：和插入一样对齐句子边界，不用让模型重发。被否：扩展会删掉模型没写进 old 的原文（old 漏了半句时，整句都会被 new 覆盖），作者的字不能在没人看见的情况下删掉。插入只是移动位置，不删字，所以插入可以挪，替换只能拒绝。
- **没改的编辑只加告警，仍算成功**。最强理由：批次里其他编辑不受影响。被否：U079 里模型正是看到成功才没有复核。告警不改变 `edits_applied`，等于继续报假账。需要部分生效时可以用 `continue_on_error=true`，不需要另开一条路径。
- **加一个 `preserve_quotes` 参数，让模型自己声明不要规范化**。最强理由：显式，不用推断意图。被否：模型得先知道有这个参数才会用，U079 那一轮它并不知道规范化器的存在。「只改引号」这个条件本身就足以说明意图，而且不会误伤改了字的编辑。

## Consequences

- 收益：
  - 模糊和近似替换不会再把两段并成一段，近似替换也不会只改跨段那处的一半、把另一段的内容重复写一遍。
  - 整段插入会按本文的分隔隔开，下一段的缩进不再接到新段落行尾。
  - 整句不会插进半句话里，近似替换不会留下半句残尾；exact 锚点以标点收尾或开头时，插入点就是锚点处，不会被挪进或挪出引语。
  - 追加接着上一块的半句话往下写时，不会被拆成新段。
  - edit 报了成功，正文就一定变了；「」→“” 的体例转换能真正生效。
- 代价：
  - 以前能「改成」的单行跨段 old 现在会报错，要求模型照抄换行重发，这一轮会多一次往返。
  - 近似 replace 的边缘落在句中时也改为报错。
  - 近似替换的跨段放弃是按分数比较的：跨段窗口里最好的一个不比段内最好的差就放弃。段内那处只是比跨段的略好一点时仍会应用，这时它本身就是最像 old 的那一处。
  - exact 锚点以逗号收尾、后面是半句话时，整句会照模型的锚点插在逗号后面，不挪到句末。这是尊重锚点的代价。
  - 插入的段落规则是按 text 的形状推断的：没有分段标记、却想另起一段的一句话仍会接在段尾。全文开头或末尾的插入用全文最常见的分隔。缩进只在前后两段缩进一致时才补，以「——」等符号开头的行不补。
  - 「只改引号」的判定只认 old/new 除引号外完全相同：换引号的同时改了字的编辑，仍按稿件体例规范化：改字的部分照常生效，引号仍是稿件原来的体例，体例转换不会生效。
  - 一条 new 与原文相同的编辑会让整批回滚（`continue_on_error=false` 时），模型需要去掉它后重发。
  - U092（两次追加之间正文缩短，前半篇消失）没有处理：edit_file 每次都重新从数据库读取正文并加行锁，覆盖来自整篇写入者（`StreamAdapter._save_file_content_sync → FileCRUD.update_file` 不校验基准版本），或前端编辑器的保存与合并。需要服务端日志确认后另行修复。
