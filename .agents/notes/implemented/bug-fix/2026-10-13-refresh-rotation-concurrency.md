# 刷新令牌并发冲突与重放保护

## Problem

同一令牌并发刷新在 User 行锁之后被顺序执行，第二个请求将刚轮换的令牌当作真实重放，撤销整个 family。单标签模块内去重无法协调共享 localStorage 的多个标签页。

## Decision

- 保留 User 与令牌行锁。仅在 `rotated`、原撤销时间起固定 10 秒内、存在替换 JTI 且同账号同 family 仍有未撤销未过期令牌时返回 409；不签发凭据、不更新轮换时间、不撤销活动后继。后继可以已经多轮轮换。
- 窗口外复用、其他撤销原因和没有活动后继仍走原来的重放吊销；注销与密码变更共用的锁和失效规则保持不变。
- 浏览器使用同源 Web Locks 串行刷新 HTTP 与写入凭据。排队获得锁后重读存储；只有同 subject、同 refresh family 与匹配 access subject 的新凭据才视为当前会话后继，不把另一登录或注销当作刷新成功。迟到的原请求 401 也可只读识别同一 family 后继，避免再次刷新或误报未登录。该检查只约束客户端状态归属，服务端继续验证 JWT。
- 没有 Web Locks 的浏览器维持现有模块去重和非凭据错误不清除存储；不自动重试刷新 POST。
- PostgreSQL 回归直接观察两个 HTTP 请求连接的 `pg_blocking_pids`，覆盖真实行锁后并发、真实重放、注销和密码变更。

## Alternatives considered

- **并发时再次签发令牌**：两个请求都能成功，但会产生额外活动分支，也需要保留可重放的凭据或再轮换，扩大安全面。选择无凭据的 409。
- **所有 revoked 令牌都给宽限**：简单且减少误登出，但会放宽注销、密码变更和长时间重放。只宽限短时间内的有效轮换链。
- **只要求直接后继仍活动**：判定严格，但第三个标签先完成下一轮时会误伤随后拿锁的旧请求。允许同 family 的多轮活动后继，窗口仍绑定原时间。
- **只做浏览器锁**：减少常见并发，但旧客户端或不支持锁的环境仍可触发撤族。服务端保留同一条窄规则。

## Consequences

被复制的已轮换令牌在 10 秒内只能得到无凭据冲突，超过窗口仍触发整族撤销。Web Locks 只覆盖同源浏览器标签；不能把网络健康或 CI 通过当作线上会话连续性的证据。无需数据迁移、依赖或云配置。
