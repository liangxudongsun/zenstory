# 写第一篇短篇

用一个失物招领故事，走完从想法、提纲到正文和局部改稿的过程。下面的人物与请求是教学示例，你可以换成自己的故事。

## 1. 建好项目

在工作台首页选择“短篇小说”，先留空想法，点击“开始创作”。进入项目后，在顶部项目切换器中点击编辑名称，把项目改为“关窗之前”。

短篇项目初始有“人物”“构思”“素材”“正文”文件夹。先用人物和构思记录已确认内容，再写正文。

## 2. 讨论三场提纲

发送下面的请求：

```text
我想写现实悬疑短篇《关窗之前》，用值班员林禾的有限视角。
车站失物招领窗口六点关闭，现在五点四十分。
沈敏来认领灰色帆布包，说对外观，却说错内袋物件。
林禾不能仅凭口头认领交包。

先给三个场景的提纲，每场列人物目标、阻力和局面变化。
沈敏为什么报错、包最后交给谁，都先列为待定。
只在对话中讨论，不写正文，不修改项目文件。
```

读完后选定原因和结局，告诉 AI 哪些建议采用。不要把未选方案一并写成事实。

## 3. 保存人物和提纲

你可以自己新建文件并粘贴内容，也可以让 AI 只创建这些文件：

| 文件夹与标题 | 类型 | 内容 |
| --- | --- | --- |
| 人物 / 林禾 | 角色 | 职责、目标、知道与不知道什么 |
| 人物 / 沈敏 | 角色 | 已选背景与动机，待定问题单列 |
| 构思 / 三场景提纲 | 大纲 | 各场变化、停止点和最终选择 |
| 正文 / 第1场 认领 | 正文 | 这一场实际采用的叙事文字 |

标题与文件类型是两件事。正文用正文类型，人物和提纲分别用对应类型。

## 4. 起草第一场

保存人物与提纲，打开“第1场 认领”，发送：

```text
先读取《林禾》《沈敏》《三场景提纲》。
只写《第1场 认领》，约600—900字，用林禾的有限视角。
通过动作与问答推进，写到沈敏说错内袋物件时停止。
不提前揭露原因，不解释沈敏的内心，不继续写第2场。
将正文写入当前文件，不创建同名副本。
```

打开文件检查写入结果：是否写到停止点，是否新增了你没接受的事实，段落是否连贯。篇幅是目标，最终采用哪些文字由你决定。

## 5. 改一个具体问题

假设正文写了“林禾知道她在撒谎”，但你想保留疑问。选中这句及必要上下文，点击“添加到对话”，再发送：

```text
只改我引用的段落。林禾只知道描述不符，还不知道原因。
把对撒谎的断定改成可观察到的动作或追问，保留包未交付。
先给替换建议，不改其他场景或人物动机。
```

采用后检查前后衔接。出现差异审阅时，明确接受或拒绝各项，再完成审阅；没有拒绝的待审项会随完成操作采用。

## 6. 保存，再继续或导出

确认正文已保存，再用同样方法推进下一场：沿用已确认资料，指定本场变化和停止位置。完成后从项目顶部或手机菜单选择“导出正文”，打开下载的 TXT 检查场景顺序和结尾。

详细操作见[编辑器](../user-guide/editor.md)、[AI 创作助手](../user-guide/ai-assistant.md)和[导出正文](../user-guide/export.md)。
